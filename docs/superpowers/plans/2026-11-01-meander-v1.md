# Meander (River Meander Simulator) v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the full v1 of the spec: a static three.js web app at meander.clydeford.net where a seeded river meanders, cuts off oxbows and builds a floodplain in a 3D valley, with a grouped control panel, Explain mode and share links.

**Architecture:** A pure-JS simulation engine (`src/engine/`) runs in a Web Worker and emits typed-array snapshots. A three.js renderer (`src/render/`) only draws snapshots. `src/config.js` holds every tunable. `src/ui/` holds the lil-gui panel, share links, cross-section panel and toasts. Vite builds to `dist/`, deployed as a Cloudflare Worker with static assets and a custom domain (the convention used by the other clydeford.net tools).

**Tech Stack:** three.js, Vite, lil-gui, vitest (engine unit tests), wrangler, Cloudflare Web Analytics beacon, MIT licence, public GitHub repo.

**Spec:** `SPEC.md` (copy of "River Meander Simulator Build Spec.md")

## Decisions taken from the open questions (confirmed by Steven 2026-11-01)

- Name "Meander", address meander.clydeford.net.
- Physically inspired, tuned to look right. Not a research tool.
- Braided rivers, terraces, man-made features: not in v1. Noted in README as future work.
- Analytics: Cloudflare Web Analytics (free), beacon in index.html.
- Licence: MIT, public repo `sjohnston1972/meander`.

## Global Constraints

- Plain JavaScript ES modules, no TypeScript.
- Engine never imports three.js; renderer never does river maths.
- Fixed simulation time step `dt` in years; speed changes steps per second only.
- All randomness through one seeded generator; same seed + settings = same river.
- Desktop only: width < 1024 px or no WebGL2 shows the "best on a desktop browser" message.
- Every tunable number lives in `src/config.js` with a comment.
- Each phase ends in a git commit; the repo is pushed to GitHub.
- Target 60 fps at 1920x1080 on default (Medium) quality.

## Review Focus

Spec-implied behaviours no unit test fully pins, most likely to bite first:

1. Neck cutoff when the splice removes almost the whole river (points near fixed ends): the engine must keep at least 8 points and never splice across the fixed ends. Test in Task 3.
2. Settings changed mid-run (width, erodibility, Omega/Gamma/alpha) must apply next tick without a reset and without NaN. Test in Task 4.
3. Speed changes must not change the outcome: running N ticks in one batch and in several batches gives identical centrelines. Test in Task 4.
4. Share link with a malformed or partial hash must fall back to defaults silently, not crash. Test in Task 11.
5. Painting hard rock while paused, then playing, must deflect the river (the erodibility grid is sampled at the bank, not the centreline). Test in Task 9.

### Task 2: Seeded RNG and centreline geometry

**Files:** Create `src/engine/random.js`, `src/engine/centreline.js`, `test/random.test.js`, `test/centreline.test.js`.

**Produces:**
- `createRandom(seed:number) -> { next():number in [0,1), range(a,b), gaussian(), int(n) }`
- `curvature(x:Float64Array, y:Float64Array) -> Float64Array` (signed, 1/m, zero at ends)
- `arcLength(x,y) -> Float64Array` cumulative s
- `resample(x, y, ds) -> {x, y}` evenly spaced by linear interpolation, keeps first and last point
- `smooth(arr, passes)` in-place 3-point moving average, ends fixed
- `initialCentreline(config, rng) -> {x,y}` straight down-valley line plus seeded wiggle; presets `straight | wiggle | sine`

- [ ] Tests: same seed gives identical 100 draws; different seeds differ. Curvature of a circle radius 100 sampled at 200 points is 0.01 within 2% in the interior. Resample of a 3-point polyline of length 100 with ds 10 gives 11 points with spacing 10 within 1e-9. Initial centreline starts at x=0 and ends at x=valleyLength.
- [ ] Run tests, fail; implement; run tests, pass.
- [ ] Commit: `feat: seeded RNG and centreline geometry`.

### Task 3: Migration and cutoffs

**Files:** Modify `src/engine/centreline.js`; Create `test/migration.test.js`.

**Produces:**
- `migrationRate(x, y, k:Float64Array, params:{omega,gamma,alpha}, ds) -> Float64Array` implementing Howard-Knutson: `R0 = k*C`, `R1 = Omega*R0 + Gamma * sum_upstream(R0 * exp(-alpha*xi)) / sum(exp(-alpha*xi))`, upstream convolution truncated where weight < 1e-3.
- `migrate(x, y, rate, dt) -> void` moves points along the local normal, ends fixed.
- `findNeckCutoff(x, y, minSeparationPoints, cutoffDistance) -> {i, j} | null` using a spatial hash of cell size `cutoffDistance`.
- `spliceCutoff(x, y, i, j) -> { x, y, loop:{x,y} }` removes points i+1..j-1, returns the loop including i and j.
- `findChuteCutoff(x, y, curvature, rng, chance, ds, width) -> {i,j} | null`.

- [ ] Tests: sine centreline amplitude 20 m, wavelength 600 m, width 60 m, k=1, after 200 steps of dt 1 the max |y| grows (> 20); and the peak x of the first bend has moved downstream (skew). A hairpin whose two limbs are 50 m apart with 40 points between: `findNeckCutoff` returns a pair with j-i >= 40; splice shortens the point count by j-i-1 and the loop has j-i+1 points. Hairpin within 5 points of either fixed end: null (Review Focus 1).
- [ ] Commit: `feat: Howard-Knutson migration and neck cutoffs`.

### Task 5: Web Worker and snapshot protocol (Spec Phase 3 part 1)

**Files:** Create `src/engine/worker.js`, `src/sim.js` (main-thread client).

**Produces:**

- [ ] Worker runs ticks on a timer accumulating `yearsPerSecond * elapsed / dt` steps, capped at `config.maxStepsPerFrame`.
- [ ] Commit: `feat: engine in a Web Worker with snapshot protocol`.

### Task 7: Floodplain features (Spec Phase 4)

**Files:** Modify `src/engine/floodplain.js`, `src/engine/engine.js`; Create `src/render/trails.js`, `test/floodplain.test.js`.

- [ ] Point bar deposition: cells that were channel last tick and are now land get `barHeight` + scroll ridge term `scrollAmplitude * sin(2*pi*year/scrollPeriod)`; surface SAND, ageing to GRASS via vegetation.
- [ ] Cut bank: cells on the outer bank at the channel edge where migration rate > `cutBankRateThreshold` get surface EARTH.
- [ ] Levees and overbank silt applied on flood ticks (distance bands from config).
- [ ] Oxbow infill: `depth -= infillRate*dt`; at depth < marsh threshold surface WETLAND; at 0 surface GRASS with a shallow scar.
- [ ] History: engine keeps a ring of centrelines every `trailInterval` years; snapshot `trails` for 50, 100, 200 years ago. `trails.js` draws them as faint lines, plus thalweg line.
- [ ] Tests: after carving a straight channel then shifting it 2 cells sideways, abandoned cells have surface SAND and height within [bedHeight, bankHeight]. After a flood tick, cells 1 cell from the bank are higher than cells 10 cells away.
- [ ] Commit: `feat: point bars, scroll bars, levees, oxbow infill, history trails`.

### Task 9: Floods, banks and plants (Spec Phase 6)

**Files:** Modify `src/engine/engine.js`, `src/engine/floodplain.js`, `src/engine/centreline.js`; Create `src/render/vegetation.js`, `src/render/effects.js`, `src/ui/toast.js`, `test/floods.test.js`.

- [ ] Discharge: yearly lognormal around `meanDischarge`; flood when random draw < `floodFrequency*dt` or on trigger; flood lasts `floodDuration` years with `floodSize` multiplier; migration scaled by `discharge^dischargeExponent`.
- [ ] Erodibility grid: seeded value noise scaled by `patchiness`, hard rock patches (value `rockErodibility`) when enabled; `paint(cells, value)` message writes ROCK cells. `k` for each centreline point samples the grid at the outer bank position.
- [ ] Vegetation grid grows `growthRate*dt` on non-channel land, stripped to 0 where bank collapses; `k_eff = k*(1 - rootStrength*veg)`.
- [ ] Bank collapse: for points with rate > `collapseRateThreshold`, chance `collapseChance*dt` gives an event, local extra migration, vegetation stripped.
- [ ] Chute cutoffs active only when `flood > 0`.
- [ ] `vegetation.js`: `createVegetation(config) -> { group, update(snapshot, density, quality) }` InstancedMesh trees (cone + trunk) and grass quads placed on cells with veg > threshold, deterministic jitter from cell index.
- [ ] `effects.js`: short-lived muddy plume sprites for cutoff and collapse events. `toast.js`: `toast(text)` bottom-left messages.
- [ ] Tests: with a rock column of erodibility 0.02 across part of the valley, after 1000 ticks the river's lateral extent past the column is smaller than in the no-rock run (deflection, Review Focus 5). Flood tick raises `snapshot.flood` > 0. Chute cutoff never fires when `flood === 0` over 2000 ticks with chance 1.
- [ ] Commit: `feat: floods, erodibility and rock painting, vegetation, bank collapse`.
